# 데이터 수집 프로그램 서비스 워크플로우 (v3)

> 데이터 수집(크롤링/스크래핑/API) 프로그램 개발 의뢰 접수부터 종료·유지보수까지의 전체 프로세스 정의 문서

---

## 전체 흐름도

```
고객 의뢰
    │
    ▼
DataCollectionService.run()
    ├─ ① 의뢰 접수                (접수서 작성, 접수 확인 회신)
    ├─ ② 요구사항 정리 및 상담      (요구사항 정의서 — 의뢰인 컨펌 ✅)
    ├─ ③ 수집 가능 여부 판단        (기술 + 법적 검토 — 불가 시 아래 ③-2 분기로 이동)
    ├─ ④ 견적 산출 및 계약          (견적서/계약서 — 의뢰인 컨펌 ✅)
    ├─ ⑤ 수집 프로그램 개발         (중간 샘플 데이터 공유)
    ├─ ⑥ 테스트 및 검수 QA          (검수 확인서 — 의뢰인 컨펌 ✅)
    ├─ ⑦ 프로그램 전달 및 사용 안내  (매뉴얼 제공, 잔금 정산 — 의뢰인 컨펌 ✅)
    ├─ ⑧ 하자보수 / 유지보수        (하자보수 기간 운영, 유지보수 계약 안내)
    └─ ⑨ 종료 및 피드백             (만족도 조사, 아카이빙)
    │
    ▼
최종 프로그램 + 사용 매뉴얼 + 프로젝트 아카이브
```

```
③-2 수집 불가능 분기
    ├─ ① 대안 검토 및 제시    (범위 축소 / 공식 API / 대체 데이터셋)
    ├─ ② 고객 통보            (기술적·법적 사유 구분 안내)
    └─ ③ 종료 처리            (사유 문서화 → 내부 DB 축적)
    │
    ▼
수집 불가 통보서 + 접수 이력 기록
```

## 1. 의뢰 접수

- 접수 채널 확인 (이메일 / 폼 / 메신저 / 유선 등)
- 의뢰 접수 시 기본 정보 확보
  - 의뢰인 정보 (개인/기업, 연락처)
  - 수집 대상 (사이트/플랫폼/DB 등, URL 포함)
  - 수집하고자 하는 데이터 항목
  - 수집 주기 (1회성 / 정기 / 실시간)
  - 데이터 사용 목적
  - 희망 납기일, 예산 범위
- 접수 확인 회신 (접수 완료 안내 및 예상 검토 기간 고지)
- 접수 내역 티켓/문서화 (담당자, 접수일, 요청 내용 기록)

**산출물:** 의뢰 접수서

---

## 2. 요구사항 정리 및 상담

- 의뢰 내용 상세 확인 및 구체화
  - 수집 항목 정의 (필드 단위: 제목, 가격, 날짜 등)
  - 수집 범위 (전체 / 특정 카테고리 / 특정 기간)
  - 수집 주기 (1회성 / 정기 수집 — 일/주/월 단위 / 실시간)
  - 결과물 형식 (CSV, Excel, JSON, DB 적재 등)
  - 실행 환경 (의뢰인 PC 실행형 / 서버 구동형 / 데이터만 납품)
- 요구사항이 모호할 경우 추가 질문 리스트업 후 재확인 — **이 단계에서 반드시 확정**
- 요구사항 정의서 작성 후 의뢰인 확인(컨펌) 받기

**산출물:** 요구사항 정의서 ✅ 의뢰인 컨펌

---

## 3. 수집 대상 서치 & 수집 가능 여부 판단

### 3-A. 기술적 검토

- [ ] 대상 사이트/서비스 구조 분석 (정적 HTML / 동적 렌더링 / API 제공 여부)
- [ ] 로그인·인증 필요 여부
- [ ] 봇 차단 수준 확인 (CAPTCHA, IP 차단, Rate Limit 등 수집 방해 요소)
- [ ] 데이터 규모 및 수집 소요 시간 추정
- [ ] 데이터 갱신 주기 및 페이지 구조 변경 리스크 평가

### 3-B. 법적·정책적 검토 ⚠️

- [ ] robots.txt 및 대상 사이트 이용약관 확인
- [ ] 개인정보(민감정보) 포함 여부 확인 — 개인정보보호법 저촉 가능성
- [ ] 저작권 보호 대상 데이터 여부
- [ ] 상업적 이용 가능 여부 및 법적 리스크 판단
- ※ 법적 리스크가 있는 경우: 조건부 수용(범위 축소) 또는 거절 판단
- ※ 필요 시 법무 검토 요청

### 3-C. 종합 판단

- 기술적 + 법적 리스크를 종합하여 **수집 가능 / 불가능** 결정
- 판단 근거 문서화 (추후 분쟁 방지 및 유사 건 재판단 시 참고자료)

**산출물:** 수집 가능성 검토 보고서

### 3-1. 수집 가능 → 4단계(견적 및 계약)로 진행

### 3-2. 수집 불가능 → 대안 제시 후 종료 처리

1. **대안 검토 및 제시**
   - 부분 수집(범위 축소) 가능 여부 검토
   - 공식 API 사용 안내
   - 유사 대체 데이터 소스 / 공개 데이터셋 제안
   - 수동 수집 등 대체 방안 검토
2. **고객 통보**
   - 불가 사유를 구체적으로 안내 (기술적 사유 / 법적 사유 구분)
   - 대안이 있는 경우 함께 제시
3. **종료 처리**
   - 케이스 종료 및 사유 문서화
   - 접수 이력 내부 DB 축적 → 유사 건 재판단 시 참고자료로 활용

**산출물:** 수집 불가 통보서

---

## 4. 견적 산출 및 계약

- 개발 난이도, 수집 규모, 납기, 유지보수 조건 기준으로 견적 산출
- 견적서 발송 및 일정 협의 → 의뢰인 컨펌 획득
- 계약 시 명시할 사항
  - 작업 범위 (요구사항 정의서 기준)
  - 납기일
  - 대금 및 지급 조건 (선금/잔금 비율)
  - 하자보수 기간 및 범위
  - **사이트 구조 변경 시 대응 정책** (무상 수정 범위 / 유상 전환 기준)
  - 법적 책임 범위 (데이터 사용에 대한 책임 소재)
- 계약서 또는 작업 확인서 체결 후 개발 착수

**산출물:** 견적서, 계약서(작업확인서) ✅ 의뢰인 컨펌

---

## 5. 수집 프로그램 개발

- 개발 환경 및 기술 스택 결정 (수집 방식: API / 크롤링 / RPA 등)
- 수집 로직 설계 및 구현
  - 요청 간격 조절 (대상 서버 부하 최소화)
  - 예외 처리 (네트워크 오류, 수집 실패, 구조 변경, 차단 대응)
  - 로깅 (수집 성공/실패 기록)
- 데이터 파싱·정제 및 저장 구조 설계·구현
- 중간 진행 상황 공유 (규모가 큰 경우 중간 샘플 데이터 전달)

**산출물:** 수집 프로그램(소스코드), 중간 샘플 데이터

---

## 6. 테스트 및 검수 (QA)

### 내부 테스트

- [ ] 샘플 데이터 수집 테스트 및 수집 정확도 검증 (샘플 대조)
- [ ] 수집 항목 누락/중복/오류 여부 확인
- [ ] 예외 상황 테스트 (페이지 없음, 네트워크 끊김 등)
- [ ] 대량 수집·장시간 구동 시 성능/안정성 확인
- [ ] 고객 요구사항과의 일치 여부 최종 확인

### 의뢰인 검수

- 샘플 결과물 전달 → 의뢰인 확인
- 수정 요청 반영 (계약 범위 내 수정 횟수 기준 적용)
- 검수 승인 후 최종 전달 단계로 진행

**산출물:** 테스트 결과서, 검수 확인서 ✅ 의뢰인 컨펌

---

## 7. 프로그램 전달 및 사용 안내

- 전달 항목 (형태 확정: 실행 파일 / 스크립트·소스코드 / 클라우드 배포 등)
  - 실행 파일 또는 소스코드
  - **사용 매뉴얼** (설치 방법, 실행 방법, 옵션 설명)
  - 실행 환경 요구사항 안내 (OS, 필요 프로그램 등)
- 초기 실행 지원 — 필요 시 원격/대면 사용법 교육
- 잔금 정산

**산출물:** 최종 프로그램, 사용 매뉴얼 ✅ 의뢰인 컨펌

---

## 8. 하자보수 / 유지보수 (A/S)

- 하자보수 기간 운영 (예: 전달 후 30일)
  - 프로그램 오류(버그) → 무상 수정
  - 대상 사이트 구조 변경 → 계약 조건에 따라 처리
- 정기 수집 건의 경우 유지보수 계약 별도 안내
- 장애/오류 접수 채널 및 문의 대응 창구 안내
- 정기 점검 주기 설정 (해당 시)

**산출물:** 유지보수 정책 문서

---

## 9. 종료 및 피드백

- 프로젝트 종료 확인
- 고객 만족도 조사 및 피드백 수집
- 발견된 이슈/개선 요청사항 정리 → 내부 기록 및 프로세스 개선에 반영
- 최종 결과 보고서 작성 및 내부 공유
- 프로젝트 이력 아카이빙 (요구사항, 소스, 이슈 내역)
- 재의뢰/추천 유도 안내

**산출물:** 최종 결과 보고서, 피드백 결과, 프로젝트 아카이브
