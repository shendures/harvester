## Product Overview
**One-liner:** 고객이 원하는 웹사이트의 데이터를 자동으로 수집해주는 맞춤형 크롤러(DataCrawler) 개발 서비스.
**What it does:** 의뢰인이 지정한 웹사이트(정적 HTML/JS 렌더링/REST API/XML)에서 필요한 데이터 항목을 자동 수집하는 데스크톱 프로그램을 건별로 맞춤 개발해 납품한다. Scrapy 크롤링 엔진과 PyQt6 GUI로 구성되어 있어, 납품받은 의뢰인은 코드 지식 없이 GUI로 수집 조건을 확인·실행하고 진행 상황을 모니터링하며 결과를 CSV/DB로 내보낼 수 있다.
**Product category:** 맞춤형 데이터 수집(웹 크롤링/스크래핑) 개발 서비스 — "직접 만들 개발 인력이 없는데 특정 사이트 데이터를 자동으로 긁어오고 싶다"는 니즈로 검색·의뢰되는 카테고리로 추정. (실제 고객이 이 서비스를 어떤 채널/키워드로 찾는지는 확인 필요)
**Product type:** 건별 계약 기반 맞춤 소프트웨어 개발 서비스(bespoke service) — SaaS/구독형이 아니라 프로젝트 단위로 실행 파일(.exe)을 만들어 전달하는 형태.
**Business model:** 요구사항 정의 → 견적/계약(선금·잔금) → 개발 → 검수 → 프로그램+매뉴얼 납품 → 하자보수(무상) → (정기 수집 건은) 별도 유지보수 계약.

**Pricing (2026-08-11, `pricing` 스킬로 설계 — 초안, 실제 계약 사례 0건이라 첫 2~3건 이후 검증·조정 필요):**

> **제품 제약 반영:** 현재 아키텍처는 프로그램 1개당 사이트(블루프린트) 1개만 지원(`guidelines/ISSUES.md` 이슈 ⑯, 2개 이상 등록 시 워커가 조용히 죽는 버그 있음 — 다중 블루프린트 재설계까지 보류, [[harvest-multi-blueprint-upgrade-plan]] 참고). 따라서 "여러 사이트 동시 모니터링"을 단일 패키지 기능으로 판매하지 않는다 — 사이트 추가는 별도 프로젝트로 취급.

*개발 견적 (1회성, 사이트 1개 기준 — Good-Better-Best):*

## Target Audience
**Target companies:** 크롤링/자동 수집 프로그램을 자체 개발할 인력이 없는 개인·소상공인·중소기업. (내부 문서상 과거 작업 사례로 대기업 성격의 의뢰도 있었던 것으로 보이나 — 예: 코드 주석상 seq_no 000010/000013 — 실명 고객사 정보이므로 마케팅 자료에 공개해도 되는지 확인 필요)

**1차 타겟 (2026-07-30 결정):** 반복적으로 가격·상품 데이터를 모니터링해야 하는 이커머스 셀러·도매업자 (예: 스마트스토어 판매자). 크몽에 "스마트스토어 가격 모니터링 자동화 툴", "도매업자를 위한 시간별 가격 기록기" 등 실제 판매 중인 상품으로 수요가 확인됨. 근거는 아래 Competitive Landscape·Differentiation·Goals 섹션과 Changelog v2 참고.
**Decision-makers:** 의뢰인 본인 — 마케팅/기획 담당자, 데이터 분석 담당자, 리서치 담당자, 또는 소상공인 대표 등으로 추정. (확인 필요)
**Primary use case:** 특정 웹사이트에서 반복적으로 필요한 데이터를 수작업 대신 자동으로 수집.
**Jobs to be done:**
- 특정 사이트의 데이터(가격, 목록, 공고 등)를 정기적으로 모니터링하고 싶다
- 대량의 데이터를 빠르고 정확하게, 사람 손 없이 수집하고 싶다
- 코딩 지식 없이도 수집 프로그램을 직접 실행·운영하고 싶다
**Use cases:**
- **(확인, 2026-07-30)** 가격 비교/모니터링 — 크몽에 스마트스토어 셀러·도매업자 대상 유사 상품이 실제 판매 중 (근거: Competitive Landscape)
- (추정) 상품·목록·상세 정보 수집 (목록→상세 2단계 수집 spider 존재)
- (추정) 로그인이 필요한 사이트의 데이터 수집
- (추정) 정기 스케줄 기반 반복 수집 (일/주/월/특정일)

> 위 항목들은 코드에 구현된 기능(spider 종류, 스케줄러, 로그인 지원 등)에서 역으로 추정한 것으로, 실제 의뢰 사례·업종 분포는 확인되지 않았습니다.

## Problems & Pain Points
**Core problem:** **[MEDIUM CONFIDENCE, 2026-08-11]** 네이버 스마트스토어는 최저가·가격비교 중심 노출 구조라, 셀러는 "지금 내가 최저가인가?"를 하루에도 여러 번 반복 확인해야 함. 수십 개 상품을 하나하나 열어 경쟁 가격을 확인하고 쿠폰·배송비·적립금까지 고려해 수동으로 가격을 조정하는 과정에서 시간이 많이 들고 실수가 잦음. (출처: keyzard.cc 콘텐츠 — 마케팅 콘텐츠 성격이라 과장 가능성 있음, 단일 소스라 검증 필요)
**Why alternatives fall short:**
- 범용 노코드 크롤링 툴은 로그인/JS 렌더링/복잡한 페이지네이션 등 실제 사이트 구조에 대응하지 못하는 경우가 많음 (추정)
- 직접 개발하려면 Python/크롤링 지식이 필요해 진입장벽이 높음 (추정)
- **(확인, 2026-07-30 → 2026-08-11 확신도 상향)** 크몽/숨고 저가 프리랜서 납품물은 대부분 1회성 스크립트라 사이트 구조가 바뀌면 재의뢰해야 함. **[HIGH CONFIDENCE — 독립된 3개 소스에서 일관되게 확인]**

  3. 클리앙 게시글+댓글(개발 외주 피해 사례, 세 번째 유사 경험이라고 밝힘): "싼 게 비지떡", 저가 프로젝트는 개발자에게 "개손해각이라 방치되기 쉬움", 댓글들도 "퍼블리셔·개발인력 부분 고용 시 대부분 불만족", "초짜들이 많아 장기 프로젝트 완수 어렵다"고 동조 — 대안으로 "지인 소개로만 개발자 구할 것"을 권함 (clien.net, 2026)

## Competitive Landscape
**Direct (2026-07-30 확인):**
- 크몽/숨고의 다수 프리랜서 개발자 — 크몽 자체 가격 가이드 기준 5만~10만원(단일 페이지 단순 수집)부터 300만~500만원 이상(대용량 분산·CAPTCHA 우회)까지 폭넓게 분포, 로그인·DB저장 포함 시 150만~300만원대. 저가 구간(5~50만원, 1회성 위주) 경쟁이 특히 심함. **(2026-08-11 추가)** 해시스크래퍼 비교 가이드는 프리랜서 시장을 건당 50만~500만원대로 추정 — 소스마다 하한선 추정치가 다르므로 참고용.
- **spiderkim** (blog.spiderkim.com, "가장 쉬운 웹크롤링") — 제조업체·브랜드 기업(자사 제품의 유통채널 가격/MAP 감시)을 타겟, 고객사 사례 콘텐츠 마케팅 진행 중.
- **hashscraper.com** ("기업용 웹 데이터 수집 플랫폼") — SaaS형 포지셔닝, 용도별 비교 가이드 콘텐츠로 검색 유입 확보 중. 자체 비교 가이드에서 프리랜서/셀프서브 SaaS/API/프록시/구독형 대행 5개 유형으로 시장을 분류하며 프리랜서의 약점(재의뢰 누적, 유지보수 불가)을 명시적으로 지적함 — Harvest의 차별화 논리와 사실상 같은 주장을 펼치고 있어 메시징 차별화 필요.

## Differentiation
**Key differentiators:**
- 정적 HTML, JS 렌더링(Selenium), REST API(JSON), XML을 모두 지원하는 범용 엔진 위에 사이트별 맞춤 로직(`custom_rules/`)을 얹는 구조 — 사이트 구조가 달라도 엔진을 새로 짜지 않고 대응 가능
- 로그인 인증이 필요한 사이트도 지원
- 납품 후 의뢰인이 GUI로 직접 재실행·스케줄링·후처리(정제) 규칙 조정 가능 (일회성 스크립트 납품이 아니라 "운영 가능한 프로그램" 납품). **단, 이 셀프서비스 범위는 재실행/스케줄링/수집 후 데이터 정제(공백·중복·결측 처리 등)에 한정** — 수집 대상 사이트의 HTML 구조 변경 대응(셀렉터 수정 등)은 코드 수정이 필요해 GUI 셀프서비스 범위 밖이며, 별도 유지보수 계약으로 다룸 (2026-07-31 코드 검증, Anxiety 항목 참고).
**How we do it differently (2026-07-31 수정):** 크몽/숨고 최저가 시장(5~50만원)은 대부분 1회성 스크립트 납품이라, 사이트 구조가 바뀌었을 때 재의뢰 자체가 되는지(담당자 연락 두절 등)조차 불확실함. Harvest도 구조 변경 대응엔 개발자 코드 수정이 필요한 건 마찬가지지만, (a) 재실행·스케줄링·후처리 조정은 GUI 셀프서비스로 즉시 가능하고 (b) 구조 변경 등 코드 수정이 필요한 대응은 계약서에 명시된 유지보수 정책(SLA)으로 대응 시점·범위가 사전에 합의되어 있다는 점이 다름. 로그인·정기수집 포함 100~300만원대 고급형 구간에 자연스럽게 위치 — 저가 프리랜서와 정면 경쟁할 필요가 없음.
**Why that's better:** 의뢰인 입장에서 진짜 문제는 "재의뢰가 발생하는지 여부"가 아니라 "재의뢰가 발생했을 때 방치되는지 여부"임. 크몽 최저가 프리랜서는 사이트가 바뀌면 대응이 불확실하지만, Harvest는 유지보수 계약으로 대응이 보장되어 있어 운영 리스크가 낮음. ("재의뢰 없음"이 아니라 "재의뢰해도 확실히 대응받음"이 정확한 주장 — 2026-07-31 이전 문구는 이 구분 없이 "재의뢰 비용이 없다"고 과장했던 것을 수정함)
